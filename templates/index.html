🎓 Viva Voce Examination Defense Guide

    

    

        

            

                
Q1: What computational model does MergeMate use?

                

                    Answer: A deterministic Finite State Machine (FSM). The parser cycles through three states:
                    STATE_NORMAL (unconflicted code), STATE_OURS (lines following <<<<<<<), and STATE_THEIRS (lines following =======). When >>>>>>> is encountered, the conflict block is packaged and the state resets to STATE_NORMAL.
                

            


            

                
Q2: Why is the FSM superior to Regular Expressions for this task?

                

                    Answer: Regular expressions using greedy dot-matching (e.g. re.DOTALL) can suffer from catastrophic backtracking ($O(2^N)$) on large or malformed files with unclosed markers. Our FSM guarantees strict $O(N)$ linear time execution and $O(1)$ auxiliary state memory while preserving original operating system line breaks (\r\n vs \n).
                

            


            

                
Q3: How does a 3-way merge conflict occur in Git?

                

                    Answer: Git computes merge results by comparing two divergent branches against their Common Ancestor ($Base$). If Branch A and Branch B both modified the same physical lines relative to the Base commit, Git cannot deduce intent automatically and outputs merge conflict markers for developer resolution.
                

            


            

                
Q4: Why decouple the Flask REST API from the Frontend UI?

                

                    Answer: Decoupling the backend into JSON endpoints (/api/parse and /api/resolve) allows asynchronous client-side state management via JavaScript fetch(). The user gets instant, zero-flicker live code previews without needing disruptive full-page HTTP form reloads.
